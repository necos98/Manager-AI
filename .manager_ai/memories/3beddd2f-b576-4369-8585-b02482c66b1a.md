When spawning background tasks via asyncio.create_task in service methods, the caller must commit() before create_task() if the background task opens a new session (session_factory). flush() alone leaves records invisible to other sessions. This bug pattern hit pipeline_run_service.py:start() where flush() was used before spawning _execute(). Tests may not catch this if they inject the same session without session_factory — the test session sees flushed data, prod doesn't.
