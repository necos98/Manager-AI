In pipeline_run_service.py _execute(), the query for the latest PipelineStepRun can return multiple rows because reject_step() creates new step runs for the same (run_id, pipeline_step_id) pair. Using scalar_one_or_none() crashes with MultipleResultsFound when 2+ rows exist. Fix: use scalars().first() with an ORDER BY to pick the latest row. This pattern applies anywhere reject_step or similar logic creates duplicate rows for a non-unique key pair.
