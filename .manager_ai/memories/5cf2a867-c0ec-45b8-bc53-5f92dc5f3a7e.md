When reject_step() creates a new PipelineStepRun for an existing (run_id, pipeline_step_id) pair, _execute() line 273 uses scalar_one_or_none() which crashes on multiple rows. Must use scalars().first() since ORDER BY started_at DESC NULLS LAST already ensures ordering. Same pattern could occur anywhere querying PipelineStepRun by (run_id, pipeline_step_id) without handling duplicates.
