Corrupted data file warnings (memories, issues, files index) in `backend/app/main.py` use plain `logger.warning()` without `exc_info=True`. The warning message includes the file path — that's enough to identify and delete/repair it. Stack traces for recoverable file corruption are noise, not signal.

Pattern: `logger.warning("Skipping corrupted X: %s", file_path)` — no exc_info.

Why: User complained about full stack trace appearing alongside "Skipping corrupted memory file". Same principle as plugin error logging (see related memory): console shows clean message, diagnostics at DEBUG level only.

Related to plugin error logging pattern but for data file loading rather than MCP connections.
