Storage modules use in-process ReadCache (TTL dict, 300s default). Four instances: issue_cache, memory_cache, file_cache (all 300s default), resource_consistency_cache (300s explicit). Read-through only. Cache keys scoped by project_path prefix (format: {project_path}:{suffix}). Watcher invalidates per-project via invalidate_prefix (not global clear). Individual write operations invalidate specific keys. clear_all_caches() (global clear) used only by test fixtures. 300s chosen because watcher is primary invalidation mechanism — TTL is safety net only for external file modifications missed by watcher. User chose in-process over Redis.
