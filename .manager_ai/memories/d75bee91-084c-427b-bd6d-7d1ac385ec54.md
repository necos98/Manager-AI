Backend error logging system implementation plan uses Option C hybrid: custom logging.Handler (ErrorFileHandler) auto-captures all logger.error()/logger.exception() calls across all 35+ modules with zero per-module changes. Explicit ErrorLoggerService.log_exception() for rich-context errors needing request context or pipeline metadata. contextvars for async-safe request context propagation (not thread-local). Random suffix for same-second collisions via os.urandom(3).hex(). Phase 1 keeps existing ErrorLoggerMiddleware JSON files alongside new plain-text files — no data loss during transition. See issue c6dfab09-d732-4943-81b7-3af28579156d for full spec and plan.
