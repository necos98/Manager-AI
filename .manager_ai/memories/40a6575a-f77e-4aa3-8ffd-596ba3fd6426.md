Issue #a600a306: `PipelineResponse` schema required `project_id` but `Pipeline` model had no such column, causing 500 on `GET /api/pipelines`. Issue #ab16fc80: Same regression hit `AgentResponse` — `project_id` reappeared after being removed in #071a4f79.

**Why:** Previous issue #071a4f79 claimed to remove `project_id` from both `AgentResponse` and `PipelineResponse`, but the fix was incomplete — the field reappeared in both schemas. Likely a merge/rebase artifact.

**How to apply:** When adding/removing fields from response schemas, verify both the schema file AND the model file match. Check git blame if a supposedly-fixed field reappears — it may have been re-introduced during conflict resolution. Both `Agent` and `Pipeline` models lack `project_id` columns — these response schemas should never include `project_id`.
