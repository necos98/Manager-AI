Refactoring c6dbf46b eliminated dual-state between Issue.status="Queued" and QueueEntry. Key changes:
- queue_add() no longer sets Issue.status to QUEUED — issue retains NEW or ACCEPTED
- queue_remove() no longer resets Issue.status — checks QueueEntry.get_pending_entry()
- REST API endpoints GET /api/queue and /api/queue/status query QueueEntry PENDING directly (not Issue.status)
- MCP queue_list now enriches output with issue_name and description
- IssueStatus.QUEUED is deprecated (enum kept for backward compat with existing data)
- The event issue_status_changed with new_status="Queued" is still emitted synthetically for frontend cache invalidation and IssueQueueService event trigger
- IssueQueueService.get_pending_entry(issue_id) added as public method
- _dequeue_and_run() transition NEW/ACCEPTED→REASONING works via update_status() which has no transition validation
