`OrchestratorService._run_agent_step()` passes `MANAGER_AI_AGENT_NAME` and `MANAGER_AI_AGENT_ROLE` as env vars to `ClaudeCodeExecutor.run()`. The MCP server's `send_agent_message` tool reads these via `os.environ.get()` to populate `AgentMessage.agent_name` and `agent_role`. If env vars are missing, defaults are "agent"/"unknown".

**Why:** Previously hardcoded — all agent messages appeared as "agent (unknown)" regardless of which agent sent them. The env var contract is the only reasonable way to pass identity through the Claude Code subprocess boundary since the MCP tool runs in a forked process.

**How to apply:** When adding new orchestrator steps or modifying the executor, ensure `MANAGER_AI_AGENT_NAME` and `MANAGER_AI_AGENT_ROLE` are always set in env_vars. When adding fields to AgentMessage that should reflect the calling agent's identity, pass them through the same env var channel.
