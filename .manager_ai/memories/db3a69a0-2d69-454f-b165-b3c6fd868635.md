`DEFAULT_AGENTS` in `agent_service.py` includes `terminal_command` for each agent — this is now an **executable shell command** (e.g., `claude -p "Write specification for issue $issue_id"`), NOT a bare task description. The field lives in the Python data structure, NOT on the Agent SQLAlchemy model — no migration needed.

`PipelineService.seed_defaults()` builds a lookup dict `cmd_by_name` from `DEFAULT_AGENTS` and sets each `PipelineStep.terminal_command` accordingly. For custom agents created after seeding, `terminal_command` defaults to empty string — the PipelineStep must be manually updated via the API/frontend.

**Why:** `_run_step()` now executes `terminal_command` directly via `create_subprocess_shell`. If it's empty or a non-executable description, the shell will fail. Previous versions wrapped the description inside a `claude -p` prompt string, but the user wants full control over the command.

**How to apply:** When adding new default agents, always include an executable `terminal_command`. When modifying an existing default agent's role, update its `terminal_command` to match. After changing DEFAULT_AGENTS, existing pipelines must be deleted and reseeded (restart backend) since `seed_defaults()` is idempotent.
