pywebview does not expose an icon parameter in create_window(). On Windows, set the window icon via ctypes Win32 API: FindWindowW → LoadImageW → SendMessageW(WM_SETICON). This must happen AFTER webview.start() creates the native window — calling it after create_window() (before start) fails because the HWND doesn't exist yet. The poll_worker callback (passed as func= to webview.start) runs after native window creation, so set the icon there.

**Critical gotcha (2026-05-27):** Do NOT set `icon_set = True` before the icon call succeeds. If FindWindowW returns 0 on the first poll_worker iteration (timing), the flag stays True and the icon is never retried. Always set the flag only after a successful return.

**AppUserModelID:** Must call `SetCurrentProcessExplicitAppUserModelID("ManagerAI.ManagerAI")` BEFORE `webview.create_window()`. Without this, Windows taskbar groups the app with python.exe and uses the Python icon regardless of WM_SETICON.

**Retry loop:** set_app_window_icon() now retries FindWindowW up to 5 times with 300ms delay. Stderr logging on each failure for visibility.

Module: backend/app/desktop_icon.py — set_app_window_icon(window_title, ico_path), set_app_user_model_id(app_id)
Icon file: logo.ico (auto-generated from logo.png by _ensure_app_icon() in start.py)
Conversion: PIL/Pillow, 4 sizes (16, 32, 48, 256 px)
Windows only (ctypes.windll), fallback silent on error.

Why: User wanted custom app logo instead of default Python icon in taskbar/title bar. ctypes chosen over pywin32 to avoid extra dependency. AppUserModelID needed because Windows 10/11 taskbar uses it for icon association.
