`PipelineRunService._safe_flush_session()` catches all exceptions from `session.flush()`, rolls back, and calls flush again — without logging the error. Type mismatches and constraint violations vanish silently. When `_execute()` assigns values to step_run columns and calls `_safe_flush_session(session)`, if the flush fails (e.g., assigning UUID string to Integer column), the transaction rolls back and the value is never persisted. This made the pipeline terminal bug invisible: `step_run.terminal_id = term_id` failed on every step with zero logs.

**Why:** Method designed to handle transient DB hiccups, but catches ValueError from type coercion too.

**How to apply:** When debugging "value not persisted" issues in PipelineRunService, suspect `_safe_flush_session`. Add temporary logging inside the except block to surface the real error. Consider adding a logger.warning in the except block permanently for visibility.
