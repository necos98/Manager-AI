During spec review for the N+1 issue relations fix, the original spec described the kanban data shape as Record<issue_id, BlockedInfo> but the actual consumer (useBlockedIssueIds) returns Set<string> and only calls .has(). The spec was overcomplicated as a result. Lesson: specs that describe data shapes must verify the actual consumer code rather than assuming. This pattern recurs — future spec review should always trace consumer code before describing interfaces.
