## Analysis Summary

User wants ability to copy text portions within spec, plan, and content tabs.

### Root Causes Found

1. **InlineEditField bug (Description tab):** onClick handler fires on mouseup, destroying text selection. Users cannot select rendered markdown without entering edit mode. Fix: check `window.getSelection().toString()` before setting editing=true.

2. **Missing code block copy buttons (all tabs):** MarkdownViewer (used by spec/plan/recap/description) has no copy button on code blocks. Standard UX pattern missing.

### Recommendation: Approach C
- Fix InlineEditField with selection check
- Add copy-to-clipboard buttons to code blocks in MarkdownViewer via custom ReactMarkdown renderers
- No new dependencies needed

### Key Files
- frontend/src/features/issues/components/inline-edit-field.tsx
- frontend/src/shared/components/markdown-viewer.tsx

### Gotchas
- InlineEditField also used for name/priority — must not break
- navigator.clipboard needs secure context (OK for localhost)
- If spec/plan/recap text not selectable, root cause in parent scroll area — needs live testing
