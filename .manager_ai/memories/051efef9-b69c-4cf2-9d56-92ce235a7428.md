## Analysis Summary

User wants ability to copy text portions within spec, plan, and content tabs in the issue detail page.

## Verified Findings

### 1. InlineEditField bug (Description tab) — CONFIRMED
**File:** `frontend/src/features/issues/components/inline-edit-field.tsx:126`
**Code:** `onClick={() => !disabled && setEditing(true)}`
**Problem:** Click handler fires on any click including after text selection (mouseup). This destroys user selection by entering edit mode. Users cannot select rendered markdown in the Description tab without being forced into edit mode.
**Fix:** Check `window.getSelection().toString()` before setting editing=true. If user selected text, don't enter edit mode.

### 2. Missing code block copy buttons (all tabs) — CONFIRMED
**File:** `frontend/src/shared/components/markdown-viewer.tsx:7-14`
**Current impl:** Simple ReactMarkdown wrapper with prose styling. No custom renderers.
**Problem:** Code blocks lack copy-to-clipboard buttons. Standard UX pattern missing across spec, plan, recap, and description tabs.
**Fix:** Add custom code block renderer with copy button via ReactMarkdown `components` prop. No new deps needed — `navigator.clipboard.writeText()` is available.

### 3. Spec/Plan/Recap tabs — text IS selectable
No `user-select: none` CSS in Card, TabsContent, or MarkdownViewer components. These tabs render MarkdownViewer directly (not inside InlineEditField). Text selection works. Only missing feature is code block copy buttons.

### 4. Tasks tab — selectable, no issues
EditableTaskList renders plain spans. DndContext pointer sensor doesn't block selection.

### Scope (affected tabs by priority):
- **Description tab** — InlineEditField bug prevents ALL text selection (high impact)
- **Spec, Plan, Recap tabs** — Text selectable, only missing code block copy buttons (medium impact)
- **Tasks tab** — No changes needed

## Key Files
- `frontend/src/features/issues/components/inline-edit-field.tsx` — line 126: onClick must check for selection
- `frontend/src/shared/components/markdown-viewer.tsx` — add custom code block renderer with copy button
- `frontend/src/features/issues/components/issue-detail.tsx` — tabs wrapper (no changes needed)

## Gotchas
- InlineEditField also used for issue name (line 107) and priority (line 115) — must not break those
- `navigator.clipboard.writeText()` needs secure context (OK for localhost, dev servers)
- Code block copy button needs Tailwind prose overrides for positioning (absolute within prose-pre)
- Description tab wraps MarkdownViewer inside InlineEditField — fix needs to handle this specific wrapper case
