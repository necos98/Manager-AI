When a SQLAlchemy relationship's foreign key is `nullable=False` and the parent model can be deleted, the relationship MUST include `cascade="all, delete-orphan"`. Without it, SQLAlchemy defaults to detaching children by setting the FK to NULL, which fails with IntegrityError.

**Why:** Hit this bug twice now:
1. Deleting pipeline steps — `PipelineStep.step_runs` had no cascade, so deleting a step tried to `UPDATE pipeline_step_runs SET pipeline_step_id=NULL`, violating the NOT NULL constraint.
2. Deleting pipelines — `Pipeline.runs` had no cascade, so deleting a pipeline tried to `UPDATE pipeline_runs SET pipeline_id=NULL`, violating the NOT NULL constraint.

**How to apply:** When defining a `relationship()` with `back_populates` where the child's FK is non-nullable and the parent is deletable, always add `cascade="all, delete-orphan"`. Existing examples in the codebase:
- `backend/app/models/pipeline.py:20` — `Pipeline.steps`
- `backend/app/models/pipeline.py:21` — `Pipeline.runs` (fixed 2026-05-28)
- `backend/app/models/pipeline_run.py:38` — `PipelineRun.step_runs`
- `backend/app/models/pipeline_run.py:39` — `PipelineRun.messages`
