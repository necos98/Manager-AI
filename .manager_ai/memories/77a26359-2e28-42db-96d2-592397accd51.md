MCP plugins use aggregator proxy pattern: single /mcp endpoint, external MCP servers connected via stdio subprocess or HTTP/SSE, tools proxied with {plugin}__ prefix. Per-project config in .manager_ai/plugins.yaml. PluginManager handles lifecycle (start/stop/enable/disable) with retry (3 in 60s, 5min cooldown). Tools are read-only declarative — access_level tag injected into descriptions for LLM awareness, real enforcement at credential level.

Why: Chosen over path-based multi-mount because Claude Code expects single MCP endpoint. User approved this approach during feasibility analysis (2026-05-13).
