mark_dispatched() originally only handled DISPATCHING → DISPATCHED (normal issue completion). When called via POST /api/queue/remove for manual removal, the QueueEntry was PENDING (not yet started), so the method found nothing and failed silently. Fixed June 2026: added fallback to _get_pending_by_issue() if no DISPATCHING entry found — same pattern as mark_failed(). Now supports both PENDING → DISPATCHED (manual removal) and DISPATCHING → DISPATCHED (auto-completion). Single-file change in issue_queue_service.py.
