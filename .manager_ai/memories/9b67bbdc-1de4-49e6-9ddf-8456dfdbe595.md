Migration a1b2c3d4e5f7 drops the FK constraint on questions.issue_id referencing issues.id. Issues are stored as file-backed records (.manager_ai/issues/), not in the SQL issues table. The FK was added by migration 04f837ab5823 but causes ask_user_question to fail with integrity errors. Workaround: Alembic batch_alter_table with copy_from (reflected table minus the FK) + recreate='always' because SQLite unnamed FKs can't be dropped by name. FK on project_id is preserved (projects ARE in DB). No Python code changes needed. Use this approach for any future unnamed FK drops on SQLite.
