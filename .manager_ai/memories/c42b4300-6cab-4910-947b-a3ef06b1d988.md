Backend agents.py and pipelines.py routers have ZERO calls to `event_service.emit()`. All CRUD operations (create, update, delete, import, seed) are silent — no WebSocket events broadcast.

Frontend EventProvider (event-context.tsx:301-351) has NO handlers for agent/pipeline event types. Compare with terminal/pipeline-run/issue events which are properly handled. 

Cross-tab and multi-user scenarios are broken — only the tab that triggered the mutation sees updates via `onSuccess` callbacks.

**Why:** Agent/pipeline CRUD was added after the initial event system. Events were never wired up.

**How to apply:** 
1. Define event types: `agent_created`, `agent_updated`, `agent_deleted`, `agent_imported`, `pipeline_created`, `pipeline_updated`, `pipeline_deleted`, `pipeline_imported`
2. Emit from router endpoints after successful operations
3. Add handlers in EventProvider to invalidate relevant React Query keys
4. Note: agents/pipelines are global (not per-project), so `project_id` may be absent — per memory `694bf6fb`, this means the generic `projectId` check at line 340 won't trigger. Need explicit per-event-type invalidation like pipeline-run events do at lines 301-312.
