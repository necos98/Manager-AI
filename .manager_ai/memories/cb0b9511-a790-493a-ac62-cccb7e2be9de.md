_run_step() in pipeline_run_service.py uses asyncio.Event + asyncio.wait() as the PRIMARY completion signal. _step_completion_events: dict[tuple[str, int], asyncio.Event] maps (run_id, step_index) to events. set_step_completed(run_id, step_index) is a module-level function imported by server.py for the finished_pipeline_step MCP tool.

Three-way wait: event_task (finished_pipeline_step called), pty_task (PTY died naturally), or timeout (MANAGER_AI_PIPELINE_STEP_TIMEOUT, default 1800s). If event_task wins → success. If pty_task wins → agent exited without calling finished_pipeline_step → step FAILED (changed 2026-05-29, was previously success via pty_died_naturally). If timeout → terminal killed, step FAILED.

**Why:** User wanted explicit step lifecycle — agents call run_pipeline_step to claim and finished_pipeline_step to complete. Event gating gives instant response when agent signals done. PTY death is now a strict failure signal — if the agent exits without calling finished_pipeline_step, the step fails. This enforces the documented protocol and prevents agents from skipping the completion signal.

**How to apply:** When adding new orchestrator features that need to wait for agent action, use asyncio.Event in _step_completion_events dict. When adding MCP tools that need to signal the orchestrator, import and call set_step_completed(). Always clean up the event in a finally block. PTY death without finished_pipeline_step = FAILED — do not add fallback-to-success logic.
