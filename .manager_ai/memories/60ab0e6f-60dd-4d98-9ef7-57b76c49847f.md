Issues are stored as YAML+markdown under `.manager_ai/issues/`, NOT in the DB `issues` table. Any FK constraint referencing `issues.id` on DB tables will fail. Migration `04f837ab5823` added `ForeignKeyConstraint(['issue_id'], ['issues.id'])` to the `questions` table — this was a mistake. The drop migration strategy: use `op.batch_alter_table('questions')` with `sqlalchemy.inspect()` to discover the auto-generated FK name (original migration had no explicit name=). `project_id` FKs are safe — projects ARE in the DB.
