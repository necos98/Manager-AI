`useActivePipelineRuns` on issues index page (issues/index.tsx:41) passes ALL issue IDs to `GET /api/pipeline-runs/active-by-issue` with `refetchInterval: 5000`. Three issues: (1) polls every 5s even when 0 active runs exist, (2) URL bloat — all issue IDs in query string, (3) WebSocket events don't invalidate this query key (event-context.tsx only invalidates `["pipeline-runs", projectId]`, not the `active-by-issue` key). Fix options: smart polling (high interval when no active runs), project-level endpoint to avoid passing all IDs, or WebSocket-driven invalidation.
