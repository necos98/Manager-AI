`_run_step()` in `PipelineRunService` spawns `claude -p` via `asyncio.create_subprocess_exec` with a proper argument list (`["claude", "-p", prompt]`), matching the proven pattern in `enrich_context.py`. Never use `create_subprocess_shell` with string interpolation — shell metacharacters in the system prompt (quotes, `$`, backticks) break the command silently, especially on Windows cmd.exe.

The prompt is a plain Python string with real `\n` newlines containing system prompt, task, issue ID, and pipeline run ID. stdout and stderr are separate pipes: stdout is streamed to the terminal log via `push_output()`, stderr is drained and logged via `logger.warning()`.

**Why:** The original `create_subprocess_shell` with f-string interpolation caused Claude Code to never launch — the shell interpreted special characters in agent system prompts, breaking the command. `enrich_context.py` already had the correct pattern but `_run_step()` was written independently with the broken shell approach.

**How to apply:** Any new subprocess spawning in pipeline steps must use `create_subprocess_exec` with arg lists. Never build shell command strings manually.
