Pipeline _run_step() now uses PTY terminals via TerminalSession.pty_dead for completion detection, not create_subprocess_shell. Each step spawns real PTY (terminal_service.create), injects env vars in shell dialect, writes command + exit, awaits pty_dead. The terminal_session.py infrastructure (TerminalSession, _sessions, _ensure_reader) was explicitly built for this purpose. Previous approach used create_subprocess_shell + log terminal (asyncio.Queue) — replaced because user wanted real PTY like RUN ISSUE flow with interactive Claude sessions.
