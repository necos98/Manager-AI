`_run_step()` in `PipelineRunService` executes the step's `terminal_command` directly via `asyncio.create_subprocess_shell(command, cwd=project_path, ...)`. The `terminal_command` is the full command string (e.g., `claude -p "Write spec for issue $issue_id"`), with `$issue_id`/`$project_id`/`$project_path` substituted by `_execute()`. stderr is merged into stdout (`stderr=asyncio.subprocess.STDOUT`) so all output is visible in the terminal.

**Why:** Previous approach hardcoded `["claude", "-p", prompt]` and embedded `system_prompt` + `terminal_command` inside a constructed prompt string. User had no control over what command runs. Now `terminal_command` IS the command — user configures it per agent/pipeline step. `create_subprocess_shell` is appropriate here because the command is a user-authored shell string, not programmatic string interpolation.

**How to apply:** `terminal_command` on pipeline steps and DEFAULT_AGENTS must be executable shell commands (e.g., `claude -p "task description"`), not bare task descriptions. Agent context (system_prompt, issue_id, run_id) is passed as environment variables, not embedded in command string.
