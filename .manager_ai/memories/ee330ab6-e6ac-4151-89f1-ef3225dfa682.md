When adding per-terminal features that depend on issue context, create a wrapper component around TerminalPanel rather than modifying TerminalPanel internals. Example: `TerminalWithQuestions` wraps TerminalPanel + QuestionCards, fetches questions via `usePendingQuestions(projectId, issueId)`. TerminalPanel stays focused on xterm rendering only.

Why: TerminalPanel is already 400 lines of xterm, WebSocket, resize, search, clipboard, file gallery, and speech logic. Adding more responsibilities (questions, issue metadata, etc.) would make it unmaintainable. Wrapper composes TerminalPanel with additional data-fetching and UI, keeping each file focused.

How to apply: For any new feature that needs to show supplementary data near a terminal (status badges, linked issues, agent output, etc.), follow the `TerminalWithQuestions` pattern — new file in `features/terminals/components/`, props include `terminalId` + `projectId` + `issueId` + passthrough, internally fetches what it needs, renders TerminalPanel + extra content.
