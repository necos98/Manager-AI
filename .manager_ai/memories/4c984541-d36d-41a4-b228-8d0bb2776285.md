The existing set_step_completed() signal is reused for both normal completion and rejection. When finished_pipeline_step MCP tool handles a rejection, it: (1) calls reject_step() to update DB, (2) calls set_step_completed() to wake up _execute(). No separate signaling mechanism needed — the wake-up and re-read approach (refresh run from DB) handles both paths.
