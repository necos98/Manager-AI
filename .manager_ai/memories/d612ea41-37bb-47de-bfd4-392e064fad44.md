After issue #071a4f79, Agent and Pipeline models no longer have `project_id`. Both are global resources shared across all projects. Migration `74be7f4de8b5` drops the column.

Key consequences:
- `AgentService.seed_defaults()` takes no arguments — seeds once globally
- `PipelineService.seed_defaults()` takes no arguments — seeds once globally
- `list_by_project()` renamed to `list_all()` on both services
- API routes moved from `/api/projects/{id}/agents` → `/api/agents`, same for pipelines
- Frontend routes moved from `/projects/$projectId/agents` → `/agents` (top-level)
- PipelineRun/PipelineStepRun remain project-scoped via issue relationship
- `project_id` added to `PipelineRunStart` schema (passed in POST body)

Why: User wanted pipelines at "software level" like agents. All projects share the same agents and pipeline templates.
