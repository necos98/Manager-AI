In async FastAPI routes using SQLAlchemy async sessions, always build Pydantic response objects BEFORE calling `await db.commit()`. After commit, the session expires all ORM objects — accessing any lazy-loaded attribute (including `updated_at` with `onupdate`) from a sync helper function triggers `sqlalchemy.exc.MissingGreenlet` because the async lazy load has no greenlet context.

**Pattern (correct):**
```python
pipeline = await svc.update(...)
response = _response(pipeline)  # build while session active
await db.commit()
return response
```

**Alternative (also correct):** Do a fresh query after commit:
```python
await db.commit()
return _response(await svc.get_pipeline(id))
```

**Why:** `MissingGreenlet` means async IO was attempted outside of an async context. Accessing expired ORM attributes triggers a lazy-load refresh, which requires async DB IO, but sync helper functions like `_response()` have no async event loop available.

**How to apply:** When writing or reviewing FastAPI route handlers, check that no ORM model attributes are accessed after `await db.commit()` — unless the object was freshly queried after the commit.
