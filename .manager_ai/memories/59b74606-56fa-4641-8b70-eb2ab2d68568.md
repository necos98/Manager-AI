In async FastAPI routes using SQLAlchemy async sessions, models with `server_default=func.now()` / `onupdate=func.now()` have their timestamp columns expired by both `flush()` and `commit()`. Expired attributes trigger lazy-load refresh → `MissingGreenlet` in sync helper functions.

**Pattern 1 — build response before commit (BROKEN when columns have server_default/onupdate):**
```python
pipeline = await svc.update(...)  # flush → updated_at expired
response = _response(pipeline)    # KABOOM: MissingGreenlet
await db.commit()
```

**Pattern 2 — commit first, re-fetch (ALWAYS CORRECT):**
```python
await svc.update_pipeline(pipeline_id, data.name)
await db.commit()
return _response(await svc.get_pipeline(pipeline_id))
```

**Why:** `MissingGreenlet` means async IO was attempted outside async context. Accessing expired ORM attributes triggers lazy-load refresh requiring async DB IO, but sync helpers like `_response()` have no async event loop.

**How to apply:** When writing/reviewing FastAPI route handlers that write models with server-side defaults: never use pattern 1. Always commit first, re-fetch, then build response. For read-only routes, both patterns safe (no expiration). See issue 18d6d9b0.
