The ErrorLoggerMiddleware catches ALL exceptions (including AppError subclasses), logs via ErrorLoggerService, and re-raises. The AppError exception handler also logs via ErrorLoggerService. This creates two error files per AppError HTTP error. Accepted tradeoff: defense-in-depth ensures coverage if either path fails, and the files differ slightly (middleware has raw exc info, handler has AppError.message). Could optimize later by having middleware detect AppError and skip re-raise, but not worth complexity now.
