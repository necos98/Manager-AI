`TerminalService._to_response()` returns a dict without `pty` key. Any code doing `existing.get("pty", None)` on `list_active()` output will always get None, making PTY-dependent cleanup dead code. Always tear down unconditionally when you know the terminal type has a PTY (e.g., manage-agent terminals), or access `_terminals[term_id]` directly to check for PTY. Bug hit in `create_manage_agent_terminal` where teardown of old terminals never executed because it checked `existing.get("pty", None)` on response dicts.
