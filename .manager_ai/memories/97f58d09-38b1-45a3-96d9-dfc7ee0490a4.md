The ForeignKey constraint on questions.issue_id → issues.id was removed because issues are file-backed (not in DB issues table). Two migrations were written: a1b2c3d4e5f7 (broken — removed from wrong collection) and ea6dc15a673c (fix — direct SQLite table recreation). Alembic's batch mode with copy_from cannot reliably remove FKs from SQLite due to SQLAlchemy memoization and Column-level FK metadata that survives constraint removal. The fix manually recreates the questions table without the issue_id FK. PRAGMA foreign_keys must be OFF during migration.
