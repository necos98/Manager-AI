NotificationService now writes a dedicated log file at backend/logs/notifications.log (append mode). Uses a separate Python logger (NotificationFileLogger) with logging.FileHandler, propagate=False to avoid root logger duplication. Format: [%%(asctime)s] NOTIFICA | %%(event_type)s | Issue: %%(issue_name)s | Progetto: %%(project_name)s | Messaggio: %%(message)s with datefmt %%%%Y-%%%%m-%%%%d %%%%H:%%%%M:%%%%S.

The _setup_notification_logger() static method handles directory creation (os.makedirs exist_ok) and deduplicates handlers by name to avoid duplicates on re-registration (e.g. tests). The handler name is 'NotificationFileHandler'. Logged in _notify_issue_finished (event_type='issue_finished') and _notify_question_asked (event_type='question_asked'). Message is truncated to 200 chars via Python slice.

Why: user requested a persistent notification audit trail separate from error logs. FileHandler was chosen over rotating handler for simplicity — notifications are low-volume.
