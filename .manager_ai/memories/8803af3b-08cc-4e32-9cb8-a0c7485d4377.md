SpecReviewer found and fixed 3 issues in SpecWriter's output for the export/import spec:

1. **Type field inconsistency** (fixed): Export wrapper used `"pipeline"` (singular) while agents used `"agents"` (plural). Changed to `"pipelines"` for consistency.

2. **Import confirm endpoint ambiguity** (fixed): Spec had 3 competing descriptions of the confirm endpoint (base64 file, resolve map, JSON-only). Cleaned to single multipart approach: file + `conflicts` JSON string field. The frontend's existing `uploadRequest` supports this pattern.

3. **Pipeline step overwrite behavior on import** (fixed): Spec didn't state what happens to existing steps on pipeline ID conflict. Clarified: full deletion + recreation from file.

**Spec quality pattern to watch**: SpecWriter produced conflicting/equivocal endpoint descriptions when iterating on design alternatives. Future specs should settle on one design before writing endpoint descriptions rather than including brainstorm alternatives.
