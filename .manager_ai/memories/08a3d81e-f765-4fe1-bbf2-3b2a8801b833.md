When building endpoints that list issues (dashboards, counts, summaries), use `list_issues()` which reads only the `issues.yaml` index — not `list_issues_full()` which loads all markdown bodies (4 files per issue: description, specification, plan, recap).

**Why:** `get_dashboard_data()` was calling `list_issues_full()` to display name/status/priority only — wasting 4N disk reads per request. `get_issue_counts()` already used `list_issues()` correctly — it was the pattern to follow.

**Rule:** Default to `list_issues()`. Only use `list_issues_full()` or `load_issue()` when the endpoint actually needs markdown body fields (description, specification, plan, recap).
