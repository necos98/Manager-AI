`useImportAgentsConfirm` (frontend/src/features/agents/hooks.ts:115-130) only invalidates `agentKeys.all()`. `useImportPipelinesConfirm` (pipelines/hooks.ts:151-166) only invalidates `pipelineKeys.all()`. 

But `PipelineService.import_pipelines` (backend/app/services/pipeline_service.py:211-290) **creates agents inline** when step agent IDs don't exist in DB — lines 249-258 and 279-288 call `self.session.add(Agent(...))`. 

So a pipeline import mutates BOTH entities. Frontend only refreshes pipelines. Agents tab stays stale until manual refresh. Similarly, agent import should invalidate pipeline queries since pipelines reference agents by ID.

**Why:** Each hook was written assuming single-entity scope, but the backend pipeline import creates agents as a side effect.

**How to apply:** Add cross-entity invalidation: in `useImportAgentsConfirm` add `queryClient.invalidateQueries({ queryKey: pipelineKeys.all() })`; in `useImportPipelinesConfirm` add `queryClient.invalidateQueries({ queryKey: agentKeys.all() })`. Also invalidate detail queries for completeness.
