Do NOT add `--worktree` flag to `ClaudeCodeExecutor` (backend/app/hooks/executor.py:76). The executor runs `claude -p` (non-interactive mode). Per Claude Code docs, `--worktree` + `-p` worktrees are never auto-cleaned — there is no exit prompt to trigger the keep/remove dialog. Each agent step would create an orphaned worktree, accumulating indefinitely.

**Why:** Claude Code only cleans up worktrees on interactive exit. Non-interactive `-p` mode skips cleanup entirely. Manual `git worktree remove` would be needed for every orphan.

**How to apply:** Worktree isolation for Manager AI's agent pipeline happens at the session level instead. Run `claude --worktree` and all agent `claude -p` subprocesses inherit the worktree directory. The `.worktreeinclude` file copies `.env` into new worktrees so config is present. See also [[worktree-project-config]].
