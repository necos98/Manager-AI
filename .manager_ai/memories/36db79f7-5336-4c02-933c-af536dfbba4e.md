Do NOT add `--worktree` flag to `ClaudeCodeExecutor` (backend/app/hooks/executor.py:76) or `HermesProvider` (backend/app/providers/hermes_provider.py). Both run non-interactive subprocesses (`claude -p` and `hermes chat -q` with `--yolo`). Per Claude Code docs, `--worktree` + `-p` worktrees are never auto-cleaned — there is no exit prompt to trigger the keep/remove dialog. Each agent step would create an orphaned worktree, accumulating indefinitely.

**Fixed in HermesProvider on 2026-06-09:** Removed `--worktree` from `build_run_issue_command()` and `build_run_pipeline_command()`.

**Why:** Claude Code only cleans up worktrees on interactive exit. Non-interactive mode skips cleanup entirely. Manual `git worktree remove` would be needed for every orphan.

**How to apply:** Worktree isolation for Manager AI's agent pipeline happens at the session level instead. Run `claude --worktree` and all agent subprocesses inherit the worktree directory. The `.worktreeinclude` file copies `.env` into new worktrees so config is present.
