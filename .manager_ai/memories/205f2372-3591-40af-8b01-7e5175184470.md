Bug pattern: `os.environ.get("KEY") or generate_key()` in crypto code silently creates unrecoverable state. Key exists only in process memory, lost on restart, permanently corrupting encrypted data. Enforced via review: all crypto/credential code must fail with ValueError when required keys are missing, never silently degrade. Fix pattern: persist key at startup to `data/secret.key` with atomic write, env var takes precedence.
