SQLAlchemy relationship() definitions use string FK references (e.g., `ForeignKey("pipelines.id")`). These resolve by column name, not column type at runtime. After PK migration from String→Integer on `id` columns, no relationship() definitions need changes — they work as-is because the column name "id" still exists on the target table. Only the model column type annotations and actual DB schema change.
