If SQLAlchemy `metadata.create_all()` is called before/outside Alembic, the DB gets the schema matching the current models — but Alembic stamps it as `head` without running intermediate migrations. This means columns added by later migrations (rejection_count on pipeline_runs, intent on agents) are missing, and columns dropped (system_prompt on agents) still exist.

Symptoms: startup cleanup (`_startup_cleanup_orphaned_runs`, `_startup_seed_defaults`) raises `OperationalError` because they query missing columns. The broad try/except in main.py swallows the error, so IssueQueueService is never initialized → 503 on all queue endpoints.

Fix: Create a "catch-up" migration that adds missing columns (rejection_count, intent) and drops extraneous ones (system_prompt). Or reset and re-run from scratch.
