In pipeline_run_service.py:_run_step(), Windows cmd.exe PTY commands using pywinpty must chain `exit` with `&` in the SAME write call: `pty.write(f"{command} & exit\r\n")`. Separate `pty.write("exit\r\n")` calls create a race condition — cmd.exe processes input line-by-line and can execute exit before the spawned process finishes (especially if claude.exe is a batch wrapper that returns immediately). On Linux, `; exit` in a single write works because bash waits for the first command to finish. Relevant memory: PTY death without finished_pipeline_step = FAILURE [[cb0b9511]].
