When specifying regex patterns for shell injection detection in plan steps, r"[\\n]" in a raw string Python regex does NOT match a newline character — it matches literal backslash or 'n'. Use r"""["\n]""" (triple-quoted raw string) so \n is interpreted as a newline control character inside the character class. This was caught by PlanReviewer during review of the command injection fix plan (issue c4efe87f). Future plans for char-validation steps should use the triple-quoted raw string pattern or explicitly note the raw-string escaping behavior.
