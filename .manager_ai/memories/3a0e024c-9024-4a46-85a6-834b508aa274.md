Added `quote_url_for_shell(url, is_wsl)` to `wsl_support.py` to prevent command injection via URLs in pty.write() calls.

**What:** Helper function that quotes URLs for safe shell insertion. WSL/bash → `shlex.quote()`, cmd.exe → double-quote wrap.

**Why:** 6 pty.write() sites in terminals.py and projects.py passed URLs (containing `host_ip` and `port`) unquoted or only double-quote-wrapped into shell commands. Malicious `host_ip` or `port` value could inject shell metacharacters.

**Files changed:**
- `backend/app/services/wsl_support.py` — added `import shlex` + `quote_url_for_shell()`
- `backend/app/routers/terminals.py` — 4 WSL export sites now use helper
- `backend/app/routers/projects.py` — 2 claude mcp add sites (WSL + cmd.exe) now use helper
- `backend/tests/test_url_quoting.py` — 8 test cases covering both dialects, metacharacters, spaces, empty URL

**How to apply:** Use `quote_url_for_shell(url, is_wsl=is_wsl_shell(shell))` whenever constructing a shell command argument from a URL. Do NOT use raw f-strings with double quotes for bash/WSL targets.
