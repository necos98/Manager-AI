`_run_step()` sets these env vars on the subprocess before executing `terminal_command`:

- `MANAGER_AI_AGENT_NAME` — agent name (e.g., "SpecWriter")
- `MANAGER_AI_AGENT_ROLE` — same as agent name
- `MANAGER_AI_SYSTEM_PROMPT` — agent's system_prompt text
- `MANAGER_AI_ISSUE_ID` — current issue UUID
- `MANAGER_AI_RUN_ID` — pipeline run UUID

These are available to `claude -p` and any other command the user configures in `terminal_command`. The full `os.environ` is also inherited.

**Why:** Previous approach embedded these directly in the prompt string passed to `claude -p`. Now that `terminal_command` is the full command, context is passed via env vars so they're available without polluting the command string.
