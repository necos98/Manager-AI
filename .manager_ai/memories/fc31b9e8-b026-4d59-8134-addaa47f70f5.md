_run_step() previously set MANAGER_AI_AGENT_NAME, MANAGER_AI_AGENT_ROLE, MANAGER_AI_AGENT_INTENT, and MANAGER_AI_ISSUE_ID env vars in the PTY subprocess before launching the agent command. These were removed (issue e3dc18ff) because they created a dual identity source with get_active_agent MCP tool.

Now _run_step() writes only the command `claude --dangerously-skip-permissions "/run-pipeline {issue_id}"` + exit. No env vars are injected. get_active_agent(issue_id) is the ONLY source of agent identity.

**Why:** Agents were confused by two identity sources (env vars + get_active_agent). They interpreted get_active_agent as querying an external entity rather than discovering their own identity, leading to loops.

**How to apply:** Do NOT add agent identity env vars back to _run_step(). If agent needs context, it comes through get_active_agent MCP tool or through the /run-pipeline command's $ARGUMENTS parameter.
