`OrchestratorService._run_agent_step()` executes `claude -p` via `ClaudeCodeExecutor.run_streaming()` as a Windows subprocess with `cwd=project_path`. WSL shell handling (path translation, `cd`, bash export) was intentionally removed in issue #535e7c4e. Claude Code CLI is a Windows executable — it accesses project files directly via Windows paths. The project `shell` setting (including WSL) applies only to interactive user terminals, not to agent step execution.

**Why:** PTY-based WSL execution added overhead (path translation, env var injection via PTY write) with no benefit since claude runs natively on Windows. The log terminal + executor pattern is simpler, faster, and already proven in the hook system.

**How to apply:** Do not re-add WSL support to `_run_agent_step()`. If cross-platform agent execution is needed in the future, use the executor's `env` dict and `cwd` parameter — not PTY shell translation.
