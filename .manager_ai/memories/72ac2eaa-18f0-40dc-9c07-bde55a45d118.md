SpecReviewer found and fixed 3 issues in SpecWriter's PK unification spec:

1. **HIGH — MemoryLink PK contradiction**: Spec claimed all 19 UUID-PK tables get auto-increment Integer PK, but MemoryLink has composite PK (from_id, to_id, relation) with no id column. Fixed: MemoryLink keeps composite PK, gains uuid column only. Updated section 1.1, added dedicated 4.2 pattern, updated AC #2/#3, added non-goal.

2. **MEDIUM — Section 3.1 SQLite steps misleading**: Described "add column → copy → add PK" sequence that doesn't work in SQLite directly. Fixed: added warning note referencing Section 5.1's actual rename/recreate approach.

3. **MEDIUM — Section 5.1 Integer-PK uuid NOT NULL**: SQLite ALTER TABLE ADD COLUMN cannot add NOT NULL without DEFAULT. Fixed: clarified two-step nullable-then-recreate approach.

Minor: moved tasks (#20) to before no-FK-change batch in migration order for logical grouping.

**Takeaway**: Composite PK tables (especially join/link tables) are easy to overlook when specifying uniform patterns. SpecWriter should explicitly flag non-standard PK structures.
