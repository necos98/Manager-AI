When removing FK constraints from SQLite tables using alembic batch mode: (1) foreign_key_constraints is a memoized copy — removing from it doesn't affect the table recreation. (2) Even src.constraints.remove(fk) doesn't work because _grab_table_elements copies Column objects with their FK metadata, and _transfer_elements_to_new_table recreates FKs from column definitions. (3) src.columns['name'].foreign_keys.clear() is also ineffective because the copy_from Table object may be re-reflected. The only reliable approach is direct SQL table recreation: CREATE new table DDL (without FK), INSERT data, DROP old, RENAME new.
