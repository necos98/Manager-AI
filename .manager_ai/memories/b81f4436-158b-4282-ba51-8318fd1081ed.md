Future specs should not refer to "relation cache invalidation" as a constraint. issue_store.invalidate_issue_cache() is a documented no-op (RAM-first architecture, no cache). After creating a relation via IssueRelationService.add_relation() or issue_store.upsert_relation(), the YAML is updated directly — no cache invalidation step needed.
