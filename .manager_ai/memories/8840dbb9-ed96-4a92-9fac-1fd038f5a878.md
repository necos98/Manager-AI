When removing IssueStatus transition validators, ONLY the VALID_TRANSITIONS check inside update_status() was removed. The spec/plan/task lifecycle guards (create_spec NEW check, edit_spec REASONING check, create_plan REASONING check, edit_plan PLANNED check, accept_issue PLANNED check, complete_issue ACCEPTED+all-tasks check) are explicitly untouched. The InvalidTransitionError exception class is still used by those methods and must not be removed. The CANCELED special case in update_status() was removed since all transitions are now equally valid. See memory 82ca7710 for the original user scoping decision.
