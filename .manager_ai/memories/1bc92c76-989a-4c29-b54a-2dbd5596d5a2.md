terminal_service.py L109 uses threading.Lock in async context. All lock access is from the same event loop thread (PTY reads use separate ThreadPoolExecutor but never touch the lock). Fix: replace with asyncio.Lock, make all 10 lock-using methods async, update ~30 callers in routers/terminal_session.py. The _terminal_reader() also accesses service._lock directly (L99, L108) — coupling smell, should use public async methods. Secondary: PTY.write() runs in event loop without run_in_executor — could block on winpty.
