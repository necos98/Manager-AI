Module-level dict _issue_completion_locks in issue_service.py grew unbounded — locks created via setdefault in complete_issue() were never removed. Fixed by adding _issue_completion_locks.pop(issue_id, None) inside the async with lock: block before return rec. pop must be inside the lock block (not after return — dead code). cancel_issue() and force_finish_issue() intentionally bypass locks and should not be modified. Existing test test_complete_issue_blocks_when_lock_held passes unchanged (its manual pop becomes harmless no-op).
