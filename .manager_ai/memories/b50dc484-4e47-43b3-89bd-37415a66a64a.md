REST router (queue.py) e MCP tools (shared_tools.py) devono usare la ref module-level issue_queue_service_ref invece di creare nuove IssueQueueService(). Ogni new IssueQueueService() registra un nuovo notifier su EventService via __init__(), inquinando la lista dei notifier. La ref è già importata in queue.py con `from app.services.issue_queue_service import issue_queue_service_ref`. Se None, rispondere con 503. Pattern già usato dall'endpoint POST /api/queue/auto-process.

FIX APPLICATO (Jun 2026): shared_tools.py ora usa issue_queue_service_ref in queue_add, queue_remove, queue_list, queue_position. Nessun IssueQueueService() residuo. Inoltre IssueQueueService ha ora due nuovi metodi pubblici: add_to_queue() e remove_from_queue() che centralizzano la logica (validazione + emissione evento). Sia MCP che REST chiamano questi metodi invece di duplicare la logica.
