`AsyncSession.no_autoflush` property returns the sync session's `_NoAutoflushContext`, which has `__enter__`/`__exit__` but NOT `__aenter__`/`__aexit__`. Using `async with self.session.no_autoflush:` silently fails — autoflush still occurs during `session.execute()`.

**Correct pattern:**
```python
with self.session.sync_session.no_autoflush:
    result = await self.session.execute(select(...))
    # no autoflush during this block
```

**Why:** `AsyncSession.execute()` spawns a greenlet that calls `sync_session.execute()`, which checks `sync_session.autoflush`. The sync `no_autoflush` context manager sets `sync_session.autoflush = False`, which the greenlet-executed code respects. The async `no_autoflush` property returns the same sync context manager — using `async with` on it doesn't work because it lacks `__aenter__`.

**How to apply:** Any time you need to prevent autoflush inside an async session block (e.g., reordering, bulk mutations that could trigger constraint conflicts mid-loop), use `with self.session.sync_session.no_autoflush:`, NOT `async with self.session.no_autoflush:`.
