The POST /api/issues/relations/batch endpoint returns {blocked_ids: string[]} rather than full relation objects per issue. This is because the sole consumer (kanban board's useBlockedIssueIds hook) only needs to check .has(id) — it doesn't inspect relation types or targets. Returning a flat list avoids serializing unnecessary relation data and keeps the endpoint response size proportional to blocked count, not relation count. If a future consumer needs full relation details per issue, either add a separate endpoint or extend this one with an optional include_details flag — don't change the default response shape (kanban depends on it).
