If an issue has status 'Queued' and needs to be processed, it cannot use create_issue_spec (requires 'New' status) or edit_issue_spec (requires 'Reasoning'). The fix is to first change the issue status to 'New' via the REST API: PATCH /api/projects/{project_id}/issues/{issue_id}/status with body {"status": "New"} (curl on port 8001). Alternatively, edit .manager_ai/issues.yaml directly AND call the API endpoint because the backend uses an in-memory cache that doesn't auto-reload from disk. After the REST call, MCP tools work normally. The 'Queued' status is deprecated — queue membership is tracked via QueueEntry table instead.
