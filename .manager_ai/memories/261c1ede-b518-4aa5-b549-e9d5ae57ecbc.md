MCP `accept_issue` no longer auto-starts the pipeline. The auto-start block was removed from `backend/app/mcp/server.py`. Pipeline must be started manually via the "Start Pipeline" button in the UI, which calls `POST /{issue_id}/start-pipeline` with `trigger_type="manual"`.

Why: User requested manual control over pipeline execution. The auto-trigger was non-blocking (try/except wrapped) so removing it had zero risk — acceptance always succeeded regardless of pipeline state.

How to apply: If pipeline auto-start is ever re-added, it must be opt-in (e.g., a checkbox or setting), not unconditional. The manual trigger_type should remain the default user-initiated path. [[pipeline-trigger-types]]
