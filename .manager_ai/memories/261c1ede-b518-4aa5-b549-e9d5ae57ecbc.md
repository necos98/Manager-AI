When an issue is accepted, OrchestratorService.start_pipeline is called with trigger_type=issue_accepted. The call is wrapped in try/except — pipeline start failure does NOT block the issue acceptance. User gets the issue accepted regardless of pipeline state.

Why: Pipeline start can fail for many reasons (no default pipeline, no agents, Claude Code spawn issues). Blocking acceptance would prevent issue progress. Users can manually start pipeline later via UI.

How to apply: If pipeline auto-start needs to be changed to blocking, add a user-facing confirmation step first — silent blocking would be a regression in UX.
