Issue tags implemented May 2026 as `tags: list[str]` in issue YAML frontmatter (not separate entities/table). 

Key design decisions:
- **Multi-tag**: each issue has 0-20 tags (user chose flexibility over simplicity)
- **No tag table**: tags live only inside issue YAML. When last issue with a tag is deleted, that tag disappears from the project. No orphan tag cleanup needed.
- **Normalization**: `_normalize_tags()` in issue_service.py — lowercase, strip whitespace, deduplicate, max 50 chars/tag, max 20 tags/issue. Applied on create and update.
- **Server-side filtering**: `GET /api/projects/{id}/issues?tag=backend` filters by tag. `GET /api/projects/{id}/tags` returns sorted unique tags from all issues.
- **URL-driven filter**: KanbanBoard reads tag from route search params (`?tag=`). Clicking a tag chip in IssueDetail navigates to that URL. Filter state survives page refresh.
- **TagInput component**: reusable autocomplete in tag-input.tsx. Supports existing-tag selection + inline creation.

Why: Simple, git-friendly, consistent with file-based architecture. Avoided over-engineering with separate tag metadata (color, description) — YAGNI per user's current needs.
