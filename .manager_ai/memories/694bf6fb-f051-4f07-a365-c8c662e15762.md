In `frontend/src/shared/context/event-context.tsx` line 299, React Query invalidation for issue queries only fires when both `projectId && issueId` are present in the WebSocket event payload. If a backend event includes `issue_id` but not `project_id`, the invalidation is silently skipped — queries stay stale, UI doesn't update.

**Why:** The guard prevents cross-project invalidation but silently drops events missing `project_id`. Backend `_emit()` in `orchestrator_service.py` was missing `project_id` in its payload, which broke all pipeline real-time updates.

**How to apply:** Any new backend event type that should trigger UI refresh MUST include `project_id` in its payload dict. Check `_emit()` call sites when adding new pipeline/orchestrator events.
