In pipeline_run_service.py _execute(), the finally block (line 234-236) calls _save_recording() and terminal_service.kill(term_id), but NEVER calls _stop_reader(term_id) or _sessions.pop(term_id, None). Each pipeline step leaks a TerminalSession object in the module-level _sessions dict. Contrast with delete_terminal endpoint (terminals.py:547-562) and _teardown_terminal() (terminals.py:35-52) which do full cleanup: stop_reader → sessions.pop → kill. Fix: add _stop_reader(term_id) and _sessions.pop(term_id, None) to the pipeline cleanup block.

Why: Sessions accumulate unbounded across pipeline runs — every step adds an entry, none are removed. Reader tasks are also not explicitly cancelled, relying on PTY death to exit naturally.

How to apply: In pipeline_run_service.py _execute(), add _stop_reader(term_id) and _sessions.pop(term_id, None) before or near terminal_service.kill(term_id) in the finally block (line 234-236). Match the pattern from _teardown_terminal().
