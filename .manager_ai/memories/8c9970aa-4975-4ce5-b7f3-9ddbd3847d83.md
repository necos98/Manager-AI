The Question SQLAlchemy model (question.py:16) has issue_id as ForeignKey("issues.id"), but issues are stored in the filesystem via issue_store (IssueRecord), not in the DB issues table. This means ask_user_question MCP tool always fails with "FOREIGN KEY constraint failed" for any issue. The questions feature is completely broken for file-backed issues. Fix options: (1) Remove the FK constraint; (2) Add a sync step that creates DB Issue records for file-based issues; (3) Store questions in the filesystem alongside issues.

Why: Issues were migrated from DB to file-based storage (IssueService reads/writes .manager_ai/ directory) but the Question model was never updated to match, creating a DB constraint that can't be satisfied.

How to apply: Any fix must handle the mismatch between file-backed issue storage and DB-backed question storage. The simplest fix is removing the FK constraint, but questions would then be orphanable.
