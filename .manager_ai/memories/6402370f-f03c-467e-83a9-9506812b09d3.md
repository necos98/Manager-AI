When reject_step() creates a new PipelineStepRun for a rejected step, two rows share the same pipeline_step_id. The _execute() loop queries by pipeline_step_id and must use .scalars().first() with ORDER BY started_at DESC (not .scalar_one_or_none()) to safely pick the latest. This pattern should be used anywhere step_runs are fetched by pipeline_step_id in rejection-capable code.
