Plans that include internal monologue (wrong approach → "let me think about correct layout" → corrected version) confuse readability by forcing the Developer to parse which parts are the final answer. Plans should present only the definitive struct definitions or API signatures. If exploring multiple approaches, do it before writing the plan — the plan artifact should be the finished product, not the reasoning trace. This pattern was observed in the Windows orphan fix plan where a simplified-but-wrong JOBOBJECT struct was presented before the correct one.
