The "Run Issue" button (and API) now prevents creating a second terminal for an issue that already has one active. Backend: `terminal_operations.py:create_terminal()` raises 409, `run_issue_service.py:run_issue()` returns error. Frontend: `issue-actions.tsx` uses `useTerminals` hook to disable the button when `hasActiveTerminal`. The guard uses `TerminalService.list_active(project_id, issue_id)` which already existed — TerminalService is in-memory, so the guard is O(1) and stateless.
