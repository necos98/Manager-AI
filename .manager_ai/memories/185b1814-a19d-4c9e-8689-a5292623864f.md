`list_issues()` stores `None` as cached record placeholder in its fallback path (`issue_store.py:165`). `list_issues_full()` reads all cached records but didn't filter out `None`, causing `AttributeError: 'NoneType' object has no attribute 'relations'` in `issue_relation_service.py`. Fixed: added `[r for r in all_records if r is not None]` filter at `issue_store.py:172`. Any new caller of `list_issues_full` must handle this pattern — `None` entries appear when the disk-index fallback is hit.
