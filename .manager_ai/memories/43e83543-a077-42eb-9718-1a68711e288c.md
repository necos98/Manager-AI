In `pipeline_run_service.py:_execute()`, fetching the latest PipelineStepRun for a (run_id, pipeline_step_id) pair must use `scalars().first()` instead of `scalar_one_or_none()`. When `reject_step()` runs, it creates a new PipelineStepRun for the same step, making the pair non-unique. `scalar_one_or_none()` crashes with MultipleResultsFound. `scalars().first()` returns the first row (ordered by started_at DESC) safely.
