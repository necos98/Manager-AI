Any backend code path that creates a terminal via terminal_service.create() must also emit a terminal_created WebSocket event so the frontend can invalidate its ["terminals"] query cache. Without this event, the terminal will not appear on the Issue detail page or the global Terminals page until a manual refresh or polling cycle.

The frontend handler at event-context.tsx:315-317 already exists:
  queryClient.invalidateQueries({ queryKey: ["terminals"] })

This was fixed in pipeline_run_service.py (issue 120b0cfd) but applies to ALL terminal creation paths. REST API endpoints (POST /api/terminals, etc.) handle this via mutation onSuccess callbacks on the calling client, but server-side terminal creation (pipelines, hooks, MCP tools) needs explicit event emission.

Why: pipeline_run_service.py created terminals with correct issue_id but didn't emit the event, causing "orphan" terminals invisible to the frontend.

How to apply: when adding a new terminal creation path, check if it's server-initiated (not triggered by a frontend mutation). If so, emit terminal_created event after create().
