Bug: `_get_fernet()` in credential_service.py silently generated random key when MANAGER_AI_SECRET_KEY not set. Key lived only in process memory — lost on restart, permanently corrupting all encrypted credentials.

Fix (2 parts):
1. **main.py lifespan** — If MANAGER_AI_SECRET_KEY env var unset, check `data/secret.key`. Read if exists; generate+write atomically if not. Env var takes precedence.
2. **credential_service.py `_get_fernet()`** — Replaced silent `Fernet.generate_key()` fallback with hard `ValueError`. Safe because lifespan now ensures key is set before any handler runs.

Fix prevents future corruption. Existing credentials encrypted with a lost key remain unrecoverable.
