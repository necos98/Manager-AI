NotificationService (app/services/notification_service.py) implementa BaseNotifier e si registra su EventService. Ascolta eventi `issue_status_changed` (con new_status == \"Finished\") e `question_asked`. Se TelegramService.is_configured() è True (TELEGRAM_BOT_TOKEN impostato), NotificationService SALT l'invio per evitare duplicati — la notifica è gestita da TelegramNotifier via Bot API diretta. Se non configurato, spawna `hermes chat -q <msg> --quiet` in subprocess come fallback. Attivato in main.py linea 337 nel lifespan. I comandi one-shot di notifica NON hanno bisogno di `--max-turns` perché sono operazioni brevi (cfr. memory cc9d8188). Attenzione: l'evento `question_asked` deve includere `issue_name` — bug fixato in shared_tools.py spostando `issue_name = issue_display_name(issue)` prima dell'emissione evento.
