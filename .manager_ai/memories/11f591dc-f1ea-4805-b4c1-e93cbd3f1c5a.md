The filesystem watcher in manager_ai_watcher.py watches .manager_ai/ for external file changes and rebuilds index YAML files. The _classify method must distinguish between content directory changes (issues/, memories/, files/ subdirectories — these trigger rebuilds) and root-level index files (issues.yaml, memories.yaml, files.yaml — these are OUTPUTS of rebuild, not inputs).

Bug: when _classify matched root index files, writing them triggered another watcher event → infinite loop → continuous issue_updated/memory_updated/file_updated events to frontend.

Fix pattern: use `parts[0] == "issues" and len(parts) > 1` not `parts[0] in {"issues", "issues.yaml"}`. The len(parts) > 1 check ensures only files inside subdirectories trigger. Root-level index files have len(parts) == 1 (just the filename).
