MCP tools should NOT fire hook events directly. The service layer (issue_service, etc.) already fires hooks as part of business logic. Firing the same hook in the MCP tool causes duplicate execution — hook listeners run twice. Always check the service implementation before adding hook_registry.fire in an MCP tool. Affected pattern: complete_issue in server.py. Root cause: MCP tool author wasn't aware the service already fired the hook.
