Issue service methods (complete_issue, force_finish_issue, etc.) already fire HookEvent hooks internally. MCP tools that call these service methods must NOT fire the same hooks again — that causes double execution. The MCP tool's responsibility is: call the service, commit, emit WebSocket events (event_service.emit), and return. Hook events belong in the service layer. Found this pattern when fixing duplicate ISSUE_COMPLETED fires in complete_issue MCP tool.
