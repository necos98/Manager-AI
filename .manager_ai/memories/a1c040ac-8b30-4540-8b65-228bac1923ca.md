## Decision
Issues have a `finished_at` datetime field, set once when status transitions to Finished (in `complete_issue`). Previously only `created_at` and `updated_at` existed — but `updated_at` changes on every update, making it unreliable for chronological closure ordering.

## Pagination pattern
- Finished column in kanban uses separate `useIssues()` call with `limit`/`offset` params
- `FINISHED_PAGE_SIZE = 10` default (constant in `kanban-board.tsx`)
- Results accumulated in `allFinished` state via `useEffect`; tag change resets offset and accumulated state
- Backend: `list_by_project` sorts by `finished_at DESC` (fallback `updated_at DESC`) when `status=Finished`, then slices `[offset:offset+limit]`
- Pagination only applied when `limit` is set — main kanban queries (no limit) unaffected

## Why
User wanted finished issues shown in chronological closure order (most recent first), paginated, with "Load more" button. Previously all finished issues loaded at once, no closure-order guarantee.

## Files
- `backend/app/models/issue.py` — `finished_at` column
- `backend/app/services/issue_service.py` — `complete_issue()` sets it, `list_by_project()` supports `limit`/`offset` with Finished-specific sort
- `backend/app/routers/issues.py` — `limit`/`offset` query params
- `frontend/src/features/issues/components/kanban-board.tsx` — separate Finished fetch + accumulation
- `frontend/src/features/issues/components/kanban-column.tsx` — `onLoadMore`/`hasMore`/`isLoadingMore` props
