Fixed race condition in IssueQueueService._dequeue_and_run() where calling _on_issue_finished() twice could start the same issue in two parallel terminals. Two fixes applied in a7301687:

1. **Lock per-progetto**: asyncio.Lock() dict per project_id in IssueQueueService.__init__() — _dequeue_and_run() acquires the lock for serialized execution per project.

2. **Marcatura sincrona QueueEntry**: await self.mark_dispatching() is called immediately after get_next_pending() and the None check, BEFORE update_status() and _emit_event(). This closes the race window: a second concurrent _on_issue_finished wont find the entry as PENDING. _on_issue_reasoning's mark_dispatching call becomes a no-op (entry already DISPATCHING) — mark_dispatching() tolerates this by checking for DISPATCHING entries if no PENDING is found.

Single file change: backend/app/services/issue_queue_service.py. No DB migration needed.
