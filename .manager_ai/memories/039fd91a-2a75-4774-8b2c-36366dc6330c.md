PipelineRunService accepts optional session_factory in __init__. The router's session is committed and closed after the HTTP response, so _execute() background task cannot reuse it. When session_factory is provided (production), _execute() creates a fresh session and closes it in finally. When None (tests), the shared session is used. Pattern: `service = PipelineRunService(db, session_factory=async_session)` in routers, `PipelineRunService(db_session)` in tests.

**Why:** Router commits session after start() returns. Background task would operate on a closed/committed session. Session factory lets _execute() create its own connection.

**How to apply:** Any new background task method in PipelineRunService must follow same pattern — use local `session` variable (set from factory if available, else self.session), call `_safe_flush_session(session)`, close in finally if own session.
