Manager AI frontend uses `next-themes` v0.4.6 with `attribute="class"` to toggle `.dark` class on `<html>`. Tailwind v4 dark variant is configured as `@custom-variant dark (&:is(.dark *))` in `index.css`. All shadcn/ui components already use `dark:` tailwind utilities throughout.

The theming system relies on CSS custom properties (oklch color space) defined in `:root` (light) and overridden in `.dark` (dark). Both blocks MUST be complete — if a variable is missing from `.dark`, components using that variable will render with light values on dark backgrounds.

Theme toggle uses `useTheme` from `next-themes` with a mounted guard to prevent hydration mismatch. Moon icon = currently light (click for dark), Sun icon = currently dark (click for light).

**Why:** Infrastructure was 80% complete before dark mode issue — `next-themes` installed, Tailwind variant active, shadcn dark utilities in use — but `.dark` CSS block only had 7 sidebar variables, which is why dark mode didn't work. Future dark mode issues should first check `.dark` block completeness.
