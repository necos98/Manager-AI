Pipeline terminal for WSL projects opens in wrong directory because terminal_service.create() sets spawn_cwd=None for WSL (UNC paths rejected by CreateProcess). The router (terminals.py:128-131) handles this by emitting `cd <posix_path>` into the PTY after creation. The pipeline runner (pipeline_run_service.py:_execute) was missing this step. Fix: after terminal creation, check is_wsl_shell(project_shell) and write `cd shlex.quote(win_to_wsl_path(project_path))` into the PTY. This mirrors the router's behavior. All callers that create WSL terminals must emit the cd — it's not handled inside terminal_service.create().
