The `intent` field on the Agent model is the primary instruction for pipeline agents. It flows through a single channel:

1. **MCP get_active_agent**: Returns {run_id, step_run_id, agent_name, agent_intent, step_index, step_status, terminal_id}. This is the SINGLE source of truth for agent context. The env var channel (MANAGER_AI_AGENT_INTENT) was removed (issue e3dc18ff) to eliminate dual-source confusion.

The run-pipeline.md command tells agents: "agent_intent — YOUR primary instruction. This is the most important field. Read it carefully and follow it."

**DEFAULT_AGENTS seed**: All 6 agents (CodebaseExplorer, BrainstormingAgent, SpecWriter, PlanWriter, Developer, Reviewer) have populated intents in `agent_service.py`. `seed_defaults()` passes `intent=data.get("intent", "")` to `Agent()`.

**Why:** Agents were calling tools blindly with no direction. Intent gives them a specific job description to follow. Dual identity sources (env vars + get_active_agent) caused agents to misinterpret get_active_agent as an external query.

**How to apply:** When adding a new default agent, always include an `intent` in DEFAULT_AGENTS. When creating agents via MCP `create_agent`, set the intent parameter. Intent should be specific and actionable: what to do, what tools to use, what NOT to do.
