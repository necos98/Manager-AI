Issues live as file-backed records (YAML+markdown under .manager_ai/issues/), not in the SQL issues table. Any DB FK constraint referencing issues.id will fail at insert time because no matching row exists. Always use plain string columns (no ForeignKey) for issue_id in new models. If an existing migration accidentally adds an FK to issues.id, create a new migration to drop it.
