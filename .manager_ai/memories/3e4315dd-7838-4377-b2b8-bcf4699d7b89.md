The user prefers conversation/chat buttons to be general, page-level actions — NOT per-item (row-level) buttons. When they want to chat about a domain (agents, projects, etc.), they want a single visible "Start Conversation" button at the top of the page that opens a terminal running the appropriate slash command.

**Examples:**
- Agents tab: "Start Conversation" button in header → terminal running `/manage-agent`. Per-agent Play buttons were explicitly rejected.
- Ask & Brainstorm page: "Start conversation" button on empty state → terminal running `/ask-and-brainstorm`

**Why:** Per-item Play/chat buttons are too small, hard to find, and don't match the user's mental model of "start a conversation about this domain." The terminal-based interaction (Claude Code slash commands) is the preferred interface over embedded chat UIs.

**How to apply:** When adding conversation functionality to a new tab/page, add a single general button at the page/tab header level. Do NOT add per-row chat/play buttons. Use the existing terminal infrastructure (`useCreate*Terminal` hooks) rather than building new chat components.
