_run_step() in PipelineRunService must handle asyncio.CancelledError by killing the subprocess (proc.kill() + await proc.wait()) and cancelling the stream_output task. Without this, subprocesses leak on pipeline cancellation (background task cancelled via PipelineTaskManager.cancel_task) and stream tasks remain pending, causing "Task was destroyed but it is pending" warnings.

**Why:** CancelledError from task.cancel() propagates through await points. If _run_step doesn't catch it and clean up, the subprocess continues running and the stream task hangs on the pipe.

**How to apply:** Every async method that spawns subprocesses in pipeline execution must have a `except asyncio.CancelledError: proc.kill(); await proc.wait(); stream_task.cancel(); raise` block.
