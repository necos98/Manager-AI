Issue c6dfab09: new per-error file logging system in backend/logs/. Key findings: (1) existing ErrorLoggerMiddleware writes JSON to daily files — needs replacement with per-error plain-text files. (2) Current logging philosophy from memories: clean console messages, tracebacks only at DEBUG level. (3) No global sys.excepthook or uncaught exception handler for non-HTTP errors. (4) Log naming: error_YYYYMMDD_HHMMSS.log with random suffix for collisions. (5) Plain text format, one file per error, no auto-cleanup. (6) Must cover: HTTP errors, validation, DB, MCP plugin, terminal service, background tasks, uncaught exceptions.
