When an MCP tool needs to block and wait for user action (e.g., ask_user_question), use asyncio.Event rather than polling. Pattern: in-memory singleton store holds `Dict[id, asyncio.Event]`; MCP tool creates question, emits WebSocket event, then `await asyncio.wait_for(event.wait(), timeout=timeout_seconds)`; when user answers via REST endpoint, service signals the event with `event.set()`. The MCP tool wakes up and returns the answer. Timeout handled via `asyncio.TimeoutError` → mark question as timed_out. This is efficient (no CPU waste) and follows the QuestionStore pattern in `backend/app/services/question_service.py`.
