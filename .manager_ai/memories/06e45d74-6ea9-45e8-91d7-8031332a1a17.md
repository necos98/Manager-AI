PipelineEventRule model (DB-backed, SQLAlchemy) with event_type (string, not enum — new types need no migration), source_step_id, target_step_id, enabled. Auto-resolve happens at MCP tool level (finished_pipeline_step) when target_step_index omitted — calls resolve_rejection_target on PipelineRunService which queries PipelineService.get_event_rule_for_step. Future event types (step_completed, step_timeout) just need: insert row + handler registration. No _execute() changes needed since reject_step already handles redirect via target_step_index. See docs/superpowers/specs/2026-06-05-pipeline-event-rules-design.md for full design.
