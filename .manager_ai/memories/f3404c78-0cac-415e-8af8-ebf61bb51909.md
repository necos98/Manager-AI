The frontend kanban board had an N+1 problem: useBlockedIssueIds fired one fetchRelations call per issue. Fixed by adding POST /api/issues/relations/batch endpoint and switching the hook from useQueries to a single useQuery. The backend MemoryStore is RAM-first so the fix was purely about eliminating redundant iteration (O(N×P×I) → O(1×P×I)). Batch endpoint created in issue_relations router; service method get_relations_for_issues scans store once. Frontend changes in api-relations.ts (fetchBatchRelations) and hooks-relations.ts (useBlockedIssueIds).
