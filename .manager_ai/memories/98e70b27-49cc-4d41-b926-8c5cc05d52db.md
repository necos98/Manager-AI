When spawning a background task via `asyncio.create_task` inside a service that runs within a database transaction, call `await self.session.commit()` BEFORE `create_task`. The background task's new session (via `session_factory()`) cannot see uncommitted records. Found in `PipelineRunService.start()` at `pipeline_run_service.py:98` — flush() was called for PipelineRun and PipelineStepRun records, but the commit happened after create_task in the router/MCP handler. Fix: insert `await self.session.commit()` at line 98, before `asyncio.create_task` at line 99. Pattern: any service that spawns background tasks via create_task while holding uncommitted DB records has this same bug.
