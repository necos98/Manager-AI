The ask_user_question MCP tool had two bugs: (1) questions.issue_id had a FK constraint to issues.id, but issues are file-backed so the FK always failed on insert — fixed by migration ea6dc15a673c which recreates the questions table without the issue_id FK. (2) The tool's error handling used `except AppError` but IssueService.get_by_id() returns None (not raises) when issue not found — fixed to check `if issue is None`. Added 5 tests: success, empty question, bad timeout, issue not found, timeout flow.
