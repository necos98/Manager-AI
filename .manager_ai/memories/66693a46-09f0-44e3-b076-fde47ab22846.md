Three new REST endpoints in /api/queue: POST /add, POST /remove, GET /position/{issue_id}. Frontend: issue detail page (IssueActions) shows "Add to Queue" or "Remove from Queue (#pos)" based on queue position status. Queue page (/queue) has Remove button per row with confirmation dialog. IssueQueueService event listener triggers QueueEntry creation on add (via synthetic issue_status_changed=Queued event). QueueEntry.mark_dispatched() used for removal (not deleted — preserves FIFO traceability). Issue retains original NEW/ACCEPTED status — QueueEntry is authoritative membership record.
