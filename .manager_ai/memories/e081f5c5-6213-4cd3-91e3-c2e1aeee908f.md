PipelineRun model has no `project_id` column. All project-scoped pipeline queries must JOIN through the `issues` table via `PipelineRun.issue_id == Issue.id`. This avoids schema changes or migrations. The new `GET /api/pipeline-runs/active-by-project?project_id=X` endpoint uses this approach — replaced the old `GET /api/pipeline-runs/active-by-issue?issue_ids=...` endpoint that caused URL bloat and 5s polling waste. Frontend hook uses adaptive polling: 5s when active runs exist, 30s when none. Query key `["pipeline-runs", projectId, "active-by-project"]` prefix-matches existing WebSocket invalidation in event-context.tsx line 310.
