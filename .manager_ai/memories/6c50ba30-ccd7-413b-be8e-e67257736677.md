Backend PipelineStepRun has a `terminal_id` column (Integer FK → terminal_commands.id, nullable). Added to PipelineStepRunResponse schema so frontend can access step terminal output. Terminals are created per-step in `_execute()` via `terminal_service.create_log()` and `step_run.terminal_id` is set. Terminals are destroyed via `destroy_log()` after step completes/fails — only RUNNING steps have valid terminal connections. Frontend `PipelineProgress` should only connect `TerminalPanel` for steps with `status === "RUNNING"` and non-null `terminal_id`.

`get_runs_for_issue()` now returns full step data (including terminal_id) — previously returned only run-level fields without steps. Query also eager-loads step→agent relationship for agent_name.

**Why:** Initial implementation missed terminal_id in both schema and response dicts. Frontend needs it to show live step output.
