Issue #0921518c: Added both composite (project_id, status) and single-column (project_id) indexes on issues table. Composite alone would serve project_id-only queries via leftmost prefix, but having both is intentional: in-memory SQLite tests use simple predicate pushdown that can miss leftmost-prefix optimization on composite indexes, causing test performance regression. Single indexes avoid this. Prod SQLite also benefits — the query planner picks the narrowest index for simple lookups. This pattern should be followed for future composite+single-column index pairs on the same leading column.
