In the lifespan decomposition, `_startup_init_write_queue` returns (wq, bw) but the write_queue injection into store modules (memory_store, issue_store, file_store) happens inside `_startup_load_projects`, not in `_startup_init_write_queue`. Rationale: the stores are only needed when projects are loaded into memory (`_load_project_into_memory` calls `store.init_project()` which triggers injection). Bundling injection with the first consumer avoids storing wq as a module-level global or threading it through intermediate functions.
