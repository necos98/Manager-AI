When a third-party library logs normal events (like client disconnects) at ERROR level via `logger.exception`, a `logging.Filter` can suppress those specific records without modifying library code. The filter inspects `record.exc_info[0].__name__` and returns `False` to suppress when the exception type matches the ignorable one.

Why: The MCP library's `streamable_http.py` logs full ERROR traceback when a client disconnects mid-POST (`ClientDisconnect` from Starlette). This is normal, not an error. Patching the library isn't practical — pipeline would revert on update.

How to apply: Define a filter class extending `logging.Filter`, override `filter(record)` to check `record.exc_info[0].__name__`, add to the target logger via `logging.getLogger("target.logger").addFilter(MyFilter())`. Pair with exception handlers and middleware catches for defense in depth.

See issue 22999916-3835-4959-a331-9ecf3bb3e982 for full implementation.
