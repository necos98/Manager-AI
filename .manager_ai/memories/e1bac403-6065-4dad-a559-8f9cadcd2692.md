Issue Queue System uses a persistent QueueRegistry (queue_entries DB table). IssueQueueService listens for issue_status_changed events: Queued → register(), Reasoning → mark_dispatching(), Finished → mark_dispatched() + auto-dequeue next pending. FIFO guaranteed by QueueEntry.order column (incremental per project), not by volatile QUEUED status. Queue tools (queue_add, queue_list, queue_remove, queue_position) on orchestrator MCP use registry instead of status queries. QueueEntry has status: pending/dispatching/dispatched/failed. Registry methods: register(), mark_dispatching(), mark_dispatched(), mark_failed(), get_next_pending(), list_queue(), list_all_global(). Auto-starts first queued issue whenever at least one pending entry exists and no issue is running (guard: pending_count >= 1, see memory _maybe_auto_start_first: guard rilassato). Migration 777aa4b0afca added queue_entries table.
