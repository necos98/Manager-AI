LLM agents using plugin gateway tools (`{plugin}__call`) cannot discover available tools or their parameters from the base description alone. Fix: after plugin connection, update the gateway tool description on FastMCP with full tool names, parameter names/types, and required/optional status extracted from `inputSchema`. Description update happens in three places: (1) inside the `_gateway` proxy function after `ensure_connected()`, (2) in `_start_one()` background pre-connect, (3) in `restart_plugin()` background pre-connect. The `build_gateway_description()` function in `plugin_proxy.py` handles formatting — accepts `list[Tool]` or `list[dict]` for both eager and lazy modes. The `_update_tool_description()` helper mutates `mcp._tool_manager._tools[name].description` directly.

Why: An LLM agent reported brute-forcing ~15 different tool names and parameter names for the MySQL plugin because the gateway description only showed `[mysql plugin — read_only] MySQL Database` with no tool/parameter metadata.
