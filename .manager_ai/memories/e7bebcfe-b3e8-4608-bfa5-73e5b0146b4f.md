`prewarm_project_cache(project_path)` in `issue_store.py` uses the index cache key (`{project_path}:__index__`) as a sentinel to detect whether the project has already been prewarmed this TTL window. If the index is cached, prewarm returns immediately.

**Why:** Checking the index key is cheaper than iterating the issues directory. The index is always cached by `list_issues()` — prewarm calls `list_issues()` at the end to seed it, and `list_issues_full()` also calls `list_issues()` after prewarm returns. This means within a single TTL window, the first `list_issues_full()` call prewarms, and subsequent calls skip.

**Gotcha:** If prewarm is called standalone (not via `list_issues_full`), it still seeds the index via the trailing `list_issues()` call. Without this, standalone prewarm calls would never skip on re-invocation because nothing else caches the index key.
