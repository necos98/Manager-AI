Pipeline step terminals are created via `terminal_service.create_log()` which returns an in-memory entry with mode="log", pty=None, and a UUID string ID. They are NOT persisted `terminal_commands` rows. Each step gets its own log terminal created at step start and destroyed after step completion. The `pipeline_step_runs.terminal_id` column is `String(36)` (UUID), with no FK to `terminal_commands.id`. This is correct — the FK was a design error that caused UUID strings to fail on Integer column insert.

**Why:** Log terminals differ from PTY terminals. PTY terminals can be persisted as terminal_commands for reuse. Log terminals are ephemeral streaming sinks for agent subprocess output, created/destroyed per step.

**How to apply:** Any new code storing terminal references for pipeline steps must use UUID strings (from terminal_service.create_log()["id"]), not integer IDs. Never add FK back to terminal_commands for this column.
