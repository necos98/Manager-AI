The refactored $issueId.tsx uses a LayoutContent sub-component (not a route-level component) inside IssueDetailPage to handle all 4 layout modes (issue-only, issue-pipeline, tabs-mode, single-terminal). IssueDetailPage itself becomes pure orchestration: URL params, queries, hook call, useEffect for title, loading/not-found guards, then delegates render to LayoutContent. This keeps the page component lean (~30 lines) while keeping rendering logic co-located in the same file (no new route-level abstraction). The alternative — extracting LayoutContent to a separate file — was rejected as over-engineering since only this page uses it.
